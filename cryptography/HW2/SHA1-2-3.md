# SHA-1, SHA-2 and SHA-3

## Overview

**SHA-1, SHA-2, and SHA-3** are families of cryptographic hash functions standardized by NIST.

They all take an input of arbitrary length and produce a fixed-length **message digest**, but they use different internal constructions.

The most important distinction is:

* **SHA-1 and SHA-2** use a **compression-function / Merkle-Damgård-style construction**.
* **SHA-3** uses a completely different **sponge construction** based on the **Keccak permutation**.

---

## Comparison

| Feature                |                           SHA-1 |                   SHA-2 |                   SHA-3 |
| ---------------------- | ------------------------------: | ----------------------: | ----------------------: |
| **Main output sizes**  |                        160 bits | 224, 256, 384, 512 bits | 224, 256, 384, 512 bits |
| **Block size**         |                        512 bits |        512 or 1024 bits |      Depends on variant |
| **Internal state**     |                        160 bits |         256 or 512 bits |               1600 bits |
| **Word size**          |                         32 bits |           32 or 64 bits |            64-bit lanes |
| **Rounds**             |                              80 |                64 or 80 |                      24 |
| **Basic construction** |            Compression function |    Compression function |     Sponge construction |
| **Underlying design**  |            Merkle-Damgård-style |    Merkle-Damgård-style |      Keccak permutation |
| **Current security**   | Broken for collision resistance |                  Secure |                  Secure |

NIST specifies SHA-1 and the SHA-2 family in FIPS 180-4, while SHA-3 is specified separately in FIPS 202.

---

# 1. SHA-1

SHA-1 was standardized in 1995 and produces a **160-bit digest**.

### Basic properties

```text
Input
  ↓
Padding
  ↓
512-bit blocks
  ↓
80 rounds
  ↓
160-bit digest
```

SHA-1 uses:

* **512-bit message blocks**
* **32-bit words**
* **160-bit internal state**
* **80 rounds**
* **160-bit output**

The internal state consists of five 32-bit words:

```text
A   B   C   D   E
```

### Construction

SHA-1 processes the message block-by-block using a compression function.

Conceptually:

```text
Message
   ↓
512-bit block
   ↓
Compression function
   ↓
Internal state
   ↓
Next block
   ↓
Compression function
   ↓
...
   ↓
160-bit digest
```

### Security status

SHA-1 is **no longer considered collision-resistant**.

In 2017, researchers demonstrated a practical collision attack by creating two different files with the same SHA-1 hash. NIST has since recommended transitioning away from SHA-1 and plans to complete its transition away from SHA-1 for cryptographic protection by the end of 2030.

Therefore:

> **SHA-1 should not be used for new applications that require collision resistance.**

---

# 2. SHA-2

SHA-2 is a **family** of related hash functions.

The main variants are:

```text
SHA-224
SHA-256
SHA-384
SHA-512
SHA-512/224
SHA-512/256
```

### SHA-256

SHA-256 is probably the most familiar member of SHA-2.

It produces:

```text
256-bit digest
```

and uses:

```text
512-bit message blocks
32-bit words
64 rounds
256-bit internal state
```

Conceptually:

```text
Message
   ↓
512-bit block
   ↓
64-round compression function
   ↓
Internal state
   ↓
Next block
   ↓
...
   ↓
256-bit digest
```

### SHA-512

SHA-512 is similar in overall construction but uses larger parameters:

```text
1024-bit blocks
64-bit words
80 rounds
512-bit output
```

NIST specifies these block, word, and digest sizes in FIPS 180-4.

### Security status

SHA-2 is currently considered secure for cryptographic applications.

NIST allows SHA-2 for applications requiring secure hash functions and specifically recommends SHA-256 at minimum for applications requiring interoperability.

---

# 3. SHA-3

SHA-3 is fundamentally different from SHA-1 and SHA-2.

It was standardized by NIST in 2015 and is based on **Keccak**, the winner of NIST's SHA-3 competition.

The SHA-3 family contains:

```text
SHA3-224
SHA3-256
SHA3-384
SHA3-512
```

It also includes the extendable-output functions:

```text
SHAKE128
SHAKE256
```

---

## The important difference: Sponge Construction

SHA-3 does not use the same type of compression structure as SHA-1 and SHA-2.

Instead, it uses a **sponge construction**.

Think of it like this:

```text
              INPUT
                ↓
             Absorb
                ↓
       ┌─────────────────┐
       │  Keccak state   │
       │    1600 bits    │
       └─────────────────┘
                ↓
             Squeeze
                ↓
             OUTPUT
```

The process has two main phases:

### Absorbing

The input is divided into blocks and absorbed into the internal state.

```text
Message
   ↓
Block 1 → Keccak permutation
   ↓
Block 2 → Keccak permutation
   ↓
Block 3 → Keccak permutation
   ↓
...
```

### Squeezing

After the entire message has been absorbed, output is extracted from the state.

```text
1600-bit state
      ↓
Squeeze
      ↓
Output
```

For SHA3-256, enough output is taken to produce:

```text
256 bits
```

---

# 4. SHA-3 Internal State

SHA-3 uses a **1600-bit internal state**.

The state can be represented as:

```text
5 × 5 × 64 bits
```

because:

```text
5 × 5 × 64 = 1600 bits
```

The 64-bit units are called **lanes**.

The Keccak permutation has **24 rounds** for the 1600-bit version used by SHA-3.

Each round contains five transformations:

```text
θ (Theta)
ρ (Rho)
π (Pi)
χ (Chi)
ι (Iota)
```

So the simplified structure is:

```text
1600-bit state
      ↓
   Round 1
      ↓
   Round 2
      ↓
     ...
      ↓
   Round 24
```

---

# 5. SHA-256 vs SHA3-256

This is one of the most important concepts.

Both produce:

```text
256-bit digest
```

but they are **not two versions of the same construction**.

## SHA-256

SHA-256 uses a compression-function-based construction.

```text
Message
   ↓
512-bit blocks
   ↓
Compression function
   ↓
256-bit chaining state
   ↓
...
   ↓
256-bit digest
```

## SHA3-256

SHA3-256 uses a sponge construction.

```text
Message
   ↓
Absorb into 1600-bit state
   ↓
Keccak permutation
   ↓
Squeeze
   ↓
256-bit digest
```

So:

```text
SHA-256
    ≠
SHA3-256
```

even though:

```text
Output(SHA-256)   = 256 bits
Output(SHA3-256)  = 256 bits
```

The **output length alone does not define the hash function**.

---

# 6. Why the constructions are different

The two algorithms have fundamentally different internal designs.

### SHA-256

Uses a chain of compression operations:

```text
Block 1
   ↓
Compression
   ↓
State
   ↓
Block 2
   ↓
Compression
   ↓
State
   ↓
...
```

### SHA3-256

Uses a large internal state and a permutation:

```text
             1600-bit state
                   ↑
                   │
Message → Absorb → Permutation
                   │
                   ↓
                Squeeze
                   ↓
              256-bit output
```

SHA-3's sponge construction also makes it possible to create **extendable-output functions (XOFs)** such as SHAKE128 and SHAKE256, where the desired output length can be selected rather than being fixed in advance.

---

# 7. Security Status

### SHA-1

**Broken for collision resistance**

* Practical collision attacks exist.
* Deprecated for new security applications.
* NIST recommends migrating away from it.

### SHA-2

**Currently considered secure**

* SHA-256, SHA-384, SHA-512 and related variants are approved for secure hash applications.
* No practical collision attack comparable to the SHA-1 situation is known.

### SHA-3

**Currently considered secure**

* Based on the Keccak permutation.
* Uses a fundamentally different construction from SHA-2.
* Provides an alternative design if weaknesses were ever discovered in SHA-2.

NIST currently states that SHA-256 and SHA3-256 are acceptable for cryptographic protection.

## Key Takeaway

> **SHA-256 and SHA3-256 have the same 256-bit output length, but they are fundamentally different hash constructions.**

**SHA-256** processes message blocks through a compression function and maintains a chaining state.

**SHA3-256** uses a **1600-bit Keccak state**, a permutation, and a **sponge construction** with absorbing and squeezing phases.

Therefore, the number **256** only tells us the **digest length**. It does not tell us how the hash function works internally.

```text
Same output size ≠ same algorithm

SHA-256   → compression construction
SHA3-256  → sponge construction
```
